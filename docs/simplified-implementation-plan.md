# 外星输入法简化版实施方案

确认日期：2026 年 11 月 12 日。状态：范围已明确，可以开始实现；本次存档未修改应用代码。

第一版实现“中文或英文词语查询 → 外星候选 → 用户点选 → 逐词组合 → 图片输出”。以高效、稳定的词和短语检索为核心，不要求精确翻译，也不需要先建立完整语法系统。

## 使用流程

普通模式由 Trime 与 Rime 提供正常中文输入。切换到外星模式后：

1. 用户用九宫格输入拼音，在中文候选栏选中“你”。
2. 确认的中文词进入内部查询区，外星候选区显示匹配字形和释义；查询词不提交到聊天输入框。
3. 用户点选外星候选，将字形或已收录的字形序列加入组合区，随后开始下一次查询。
4. 输入“食物”，重复查询与点选。英文词可通过英文查询方式确认后进入同一检索引擎。
5. 用户可删除或替换已选项目，预览组合结果，主动插入 PNG；接收方不支持时提示并提供分享入口。

每次查询既可以是单词，也可以是“你好”“吃饭”等短语。第一版以用户明确确认的查询为边界，不对未确认的九宫格拼音或整句进行自动语义切分。

图片稿中的单位是一次选择的条目，一条词组可能包含多个字形。替换和删除以该单位操作，不误删整个词组中的部分字形。发送被拒时保留当前稿件；切换输入框时明确处理会话，防止把前一输入框的内容误发到下一处。

## 词典和检索

每个条目记录稳定编号、目标字形序列、显示释义、中文或英文检索别名、必要的义项区分与用法提示，以及来源。相关概念使用独立关系维护，不能伪装成同义别名。

先导入上游已有释义、词组与适用的搜索别名，再通过独立补充文件维护人工整理的常用说法。重跑导入不得覆盖补充词条；带有字形结构用途的字段不能直接当作语义别名。英文只对已收录释义和别名提供匹配，逐步补充词典。

候选优先级为释义精确匹配、别名匹配、明确维护的相关概念和保守的模糊匹配。词组允许整体命中。相同层级内可按本机使用频率排序，频次不应把关联项提升到精确匹配之前。

同一字形经多个检索词命中时合并展示；不同含义需保留可辨识的说明。无结果时明确显示，允许修改查询，不任意输出默认候选。第一版不依赖大模型、向量服务或网络查询。

## 组件边界

| 组件 | 职责 |
| --- | --- |
| 词典导入与校验工具 | 生成有版本的检索数据，校验条目、字形引用和来源 |
| 独立词义检索引擎 | 查询规范化、匹配、去重、排序，返回匹配原因 |
| Trime 与 Rime 适配 | 中文候选确认、外星模式内部查询、正常输入切换 |
| 外星候选与组合界面 | 字形预览、释义、选择、删除和替换 |
| 图片输出适配 | 生成 PNG、提交内容、处理拒收和分享 |

“外星插件”是产品功能模块名称，不预设能以独立 APK 插件实现。第一步核实 Trime 接入点，按需要做小范围宿主修改。检索引擎保持独立，未来 Linux 端可复用数据格式和行为规范。

## 实施顺序和完成标准

### 第一步 接入验证与词典检索

核实并固定 Trime 及 Rime 相关版本，验证九宫格方案与构建链路，找出确认中文候选后进入内部查询的接入点。同时建立独立词典导入与检索模块。

完成标准：能够以“你”“食物”和整理后的别名查出正确条目；匹配层级、去重、无结果和词组序列均有测试。记录目标设备上的查询耗时，为候选更新设定实际可测的延迟基线。

### 第二步 完成逐词组合闭环

接通中文确认、外星候选、点选追加、替换删除、预览和输出。普通模式保持正常中文提交；外星模式查询词不泄漏到目标应用。

完成标准：真机连续查询“你”“食物”并选取后，组合顺序正确；改词和退格行为清楚；快速修改查询不会显示旧结果。PNG 接收成功与拒收两条路径分别验证，分享和目标聊天应用兼容性单独记录。

### 第三步 打磨日常输入

九宫格为默认优先验收布局，随后验证全拼和双拼方案切换。检查中英文查询、普通输入切换、横竖屏、键盘避让、会话清理及个人排序。

完成标准：在用户常用输入布局和目标应用里走通完整流程，再交付可安装测试版本。支持某一 Rime 方案不等于该方案已通过本项目真机验收。

## 当前工程与开工条件

开发目录为 ~/project/alien-input-android，共享开发环境在 ~/project/dev-env。当前已有 Java IME 原型、字形资源、码表匹配、图片组合与输出代码，可作为迁移参考和可复用资产。

现有原型不包含 Trime 集成与词义检索。既有直接 SDK 构建脚本服务于原型；Trime 的 Gradle、原生编译和依赖环境需要按选定版本补齐。

此前真机已验证部分候选操作、文本提交和测试页面 PNG 接收。界面避让修复已构建，但未完成后续实机复验；跨应用图片、分享和横竖屏仍需验证。项目旧 README 中“尚未连接设备”的描述已过时，不作为当前验收依据。

这些事项属于实施任务，当前没有需要用户补充才能开始的产品范围问题。开发从接入验证和独立词典检索开始，保留现有原型便于对照。
