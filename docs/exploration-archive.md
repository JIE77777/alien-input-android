# 外星输入法探索阶段讨论存档

存档日期：2026 年 11 月 12 日。

本阶段讨论用于探索产品形态与语义映射的长期方向。当前开发范围以《外星输入法简化版实施方案》为准；完整语言分析与句子生成不作为第一版的前置条件。本文件是讨论纪要，不是逐字聊天记录。

## 产品目标和输入法基座

用户希望通过熟悉的中文或英文输入寻找外星表达，逐步形成可以日常使用的 Android 输入法。主要使用九宫格，同时考虑全拼和双拼。Linux 和多端同步属于后续加分项，当前优先 Android。

基座方向确定为 Trime 同文与 Rime：前者提供 Android 输入界面与系统集成，后者负责拼音转换等输入能力。Fcitx5 与 Rime 的关系和组合可能性曾被讨论，但没有成为当前 Android 实施路线。

开发目录为 ~/project/alien-input-android，共享环境为 ~/project/dev-env。已有原生 Java 字根输入原型；Trime 迁移尚未完成。

## 核心问题的演变

最初考虑根据日常表达检验体验，例如输入“你好”或“一起吃饭吗”寻找合适表达。随后明确：仅维护少量场景模板缺乏可扩展性，语义映射应成为有组织的数据与算法组件。

探索阶段进一步讨论了从源语言语义结构映射到外星语言结构，包括参与者、动作、否定、疑问、共同参与、语用意图及信息损失。最新决定将首版映射单位收敛为词和短语，由用户选择候选并组合，无需自动理解或生成整句。

## 语言学研究方向

若未来需要句子级辅助，可借用以下分析方法：

- 区分字形结构、构词单位和词义，避免将输入法拆码视为语义分解。
- 区分多义、近义、相关概念及上下文限制。
- 研究动作及其参与者、修饰关系、否定与疑问的作用范围。
- 区分字面意思与交际目的，例如“你好”的问候功能和“一起吃饭吗”的邀请用法。

与中英互译相比，目标语言的部分规则可能较少，但可用语料、经过验证的语法和独立判定依据也少。不能因为词表规模有限就认定翻译容易，更不能凭直觉补出游戏语法。

上游研究释义与别名可用于检索，但不等于官方释义。图形构成也不自动代表词义组合。具体语言规则应由游戏用例、上下文和对照材料支撑，允许保留分歧与待验证分析。

## 曾讨论的完整系统

长期架构曾考虑六类对象：字形、义项、语义关系、构式、映射规则与证据。运行时先产生源语言的可能解释，再检索和组合目标表达，检查参与者、否定、作用范围等重要信息，说明保留、丢失或新增的意义。

这一方向强调可解释和可追溯：规则记录来源、适用条件和版本；用户选择只影响个人排序，不直接证明语言规则成立。大模型可以在未来提出候选分析，但不直接自由生成未经约束的外星语句。

评估应针对固定版本词典、规则集合和测试样本；不使用缺乏明确分母的“日常表达覆盖率”。完整系统的正反例测试和语言学研究暂存为后续方向。

## 典型例子和边界

- “你”和“食物”：分别检索对应候选，由用户依次加入组合区。
- “你好”：可以维护经人工整理的问候查询别名，不必拆成“你”与“好”。
- “一起吃饭吗”：当前不自动生成译句；用户可拆成自己需要的词或短语查询。
- “食物”与“吃喝”：可以建立相关关系，不应无提示地当作同义词。
- “合在一起”与“共同参与”：不能仅凭中文相似就视为同一个语义。

这些例子用于界定产品行为，不构成目标语言语法结论。
