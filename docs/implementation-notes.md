# 简化版实现记录

> 最新迭代：`four-slot-numbers-update.md`；阶段收敛范围见 `checkpoint.md`。以下为早期实现历史记录。

当前源码位于 ~/project/alien-input-android。原 Java 字根输入法保留在 app/，新增 Trime 基座位于 trime/。独立语义模块不依赖 Android；Android 面板通过 Host 接口接入 Trime。

## 已实现的模块

- semantic-core：词义检索、匹配原因、排序、整词组合、PNG 编码读写。使用 Java 8，便于现有 JDK 独立测试和 Kotlin 宿主调用。
- lexicon：上游数据编译结果及独立维护的人工补充查询词；现有 2264 条字形和词组，2749 条检索项。10 个纯字形别名被排除并记录在生成清单中。
- android-integration：内部查询编辑器、外星候选分页、词组追加和替换、整词删除、预览、复制组合 PNG、图片插入与显式分享、复制字形编码。输入法原工具区的“外星”开关控制展开和收起，默认不显示整条外星栏；同一会话收起后保留草稿并恢复普通输入。
- rime：基于朙月拼音简化字方案的九宫格编码和键盘布局；另提供全拼与官方小鹤双拼方案入口。九宫格的词频和歧义消解来自 Rime 词典，尚需完整输入法真机验收。
- trime：固定在 v3.3.13，对输入连接和键盘面板做局部接入。包名为 io.github.alieninput.trime.debug，与原型和官方同文分开安装。

普通模式保留 Rime 正常文本输入。外星模式中，所有取词、拼音预编辑、英文字符和退格操作使用内部编辑缓冲；图片发送显式访问真实输入框。密码和非文本输入框不启用外星模式，声明不学习的输入框不使用或更新外星候选频次。

## 构建

先加载 ~/project/dev-env/android-env.sh，然后在开发根目录执行：

```sh
bash tools/test-semantic.sh
bash tools/build-trime.sh
```

Trime 构建依赖 Gradle 9.8.1、Android Platform 37 和 Build Tools 37.0.0。首次构建需要下载 Maven 依赖。开发构建使用同一提交对应的官方 arm64 APK 中的预编译 Rime 库及配套数据；脚本按官方发布元数据 SHA256 校验，不混用不同版本的 JNI 接口。

源代码锁定：

- Trime：b5cad1a49095a3652e9188982de400ca3a653f37。
- Trime 所引用 librime：56737cd29a4d393a104a2098ece3697aa2810465。
- rime-double-pinyin：01a13287cbd27819be1c34fa1ddc1b3643d5001b。
- 外星字形与词典：alien-input v6.12.4；输入数据及补充词表哈希见 lexicon/generated/manifest.json。

词典重新编译使用 tools/import_lexicon.py，参数为上游源码目录。人工补充写在 lexicon/supplements.json，导入不会覆盖此文件。

## 图片的可恢复编码

原始 PNG 的标准 tEXt 块使用 AlienInput 关键字，保存如下版本化文本：

```text
ALIEN1|v6.12.4|F0835;F1050,F1047
```

分号分隔用户选取的词组，逗号分隔一个词组内的字形。上例是两个选择项，第二项包含两个字形。只记录字形和词组边界，不记录中文或英文原始查询。

“编码”按钮可复制同样的文本，作为独立的传输载体。开发工具可以从 PNG 读回编码：

```sh
bash tools/read-png-message.sh /path/to/message.png
```

读回会检查 PNG CRC、长度和编码版本。未知版本或损坏数据会报错，没有元数据会明确返回未找到；不会根据像素猜测。编码读回恢复的是字形序列，并不是精确的中文回译，也不构成内容真实性认证。

聊天软件可能重命名或重新编码图片，截图也不携带原文件元数据。因此 PNG 元数据与文本编码并存；图片文件名不是主要编码载体。移动端导入恢复界面和任意截图识别尚未实现。

## 验证范围

桌面检索测试通过 9794 项检查，涵盖全量词条可达性、匹配层级、去重、词组边界、长度限制和错误数据处理；PNG 和文本编码往返测试也通过。

Android 16 实机独立测试通过 1427 项检查，包括内部查询、候选点选、词组替换删除、图片拒收后保留、成功提交后清空、PNG 生成与元数据读回、展开收起和草稿保留，以及官方 Rime 原生库上的九宫格、全拼、小鹤双拼中文候选提交。固定查询集测得 P50 约 0.40 毫秒、P95 约 0.61 毫秒；这是本机测试结果，不是所有设备的性能承诺。

完整 Trime APK 已构建并安装到手机。真实触屏已验证九宫格 64 → 你、74498 → 食物，两次中文确认分别匹配外星候选并合成同一草稿；复制图后在自带试写框粘贴为图片，草稿保留。普通模式的“你”上屏也通过。通过键盘内方案菜单切换全拼后，真实触屏 nihao → 你好 → 外星“问候”匹配通过，未再出现 nih 原样进入查询的问题。

修复了一处完整宿主测试才暴露的配置遗漏：手机默认主题为 tongwenfeng.trime.yaml，最初仅向 trime.yaml 加了九宫格布局，使九宫格引擎回退到全键盘；n/i/h 原样提交、a 开始组词正是这种不一致的表现。现在两个内置主题均注入对应布局和按键动作，设置已实际显示九宫格、全拼与小鹤双拼。

微信中曾出现 content:// 图片 URI 作为文字的报告。按照用户偏好，不自动进入分享流程；保留“复制图”供手动粘贴，微信隐藏不兼容的“插入图”。自带试写框已验证图片剪贴板，微信实际图片粘贴仍需单独确认，不能据此宣称兼容所有聊天应用。横竖屏与其他主题尚未完成验收。
